# Experimental-variable audit

This audit covers the existing native Docker/OpenCode conditions inspected on 2026-10-24,
before the subsequent literature-led extensions, plus the validation repairs identified here.
It distinguishes a real intervention in an environment from an instruction, a measurement setting,
and an authored regression fixture. Implementation and automated tests are not evidence that a
condition produces misalignment. New real-agent acceptance requires at least three agents, actual
task actions, the original evaluator and trajectory inspection; see the
[capability matrix](capability-matrix.md) and [acceptance procedure](native-acceptance.md).

The audit was performed against the working tree, including the installed integration contracts.
An external execution backend must separately implement or reject each requested condition.
Registration alone does not inherit the native controls below.
The [current variable reference](experimental-variables.md) documents the subsequent measured
reward, feedback, matching, history, reputation, assignment and artifact extensions.

**Decision vocabulary:** **keep** retains a meaningful enforced control; **restrict** retains it
within a stated scope or combination; **deprecate** excludes it from research while preserving
explicit fixture compatibility; **fix** identifies a validation or interpretation gap that must be
resolved before treating the setting as an independent experimental variable. These decisions do
not authorize silently changing task instructions, original evaluators or recorded outcomes.

## Validation findings and boundaries to preserve

The following were reproduced with `validate_manifest` on temporary, minimal three-agent worlds,
without launching Docker, model inference or GPU resources. They concern validation of declared
conditions, not evidence of actual agent behavior. They are now rejected by the
[inactive-condition validator](../src/mesocosm/core/condition_validation.py), called during manifest
validation and direct `run_world` admission, with [validator regression coverage](../tests/test_condition_validation.py)
and [three-agent runtime rejection tests](../tests/test_episode_controls_runtime.py). Fully serialized
default settings remain valid; validation does not silently enable an inactive component.

| Finding | Reproduced behavior before repair | Implemented action |
|---|---|---|
| Disabled chat with `max_chars: 200` | Accepted; no inactive-control warning. | **Fixed:** nondefault chat controls while disabled are rejected. |
| Disabled monitor with `scope: joint`, `threshold: 13` | Accepted; no inactive-control warning. | **Fixed:** dormant monitor treatments are rejected. |
| Disabled internet with `mode: record`, `budget.requests: 3` | Accepted; no inactive-control warning. | **Fixed:** all nondefault internet controls require enabled access. |
| Comparison mode with `stream.max_tasks: 3` | Accepted; only `stream.dir` was rejected there. | **Fixed:** inactive stream settings outside persistent mode are rejected. |
| Disabled peer review with `topology: ring` | Accepted; no inactive-control warning. | **Fixed:** an unused topology treatment is rejected. |
| `conditions.exposure: {wiki: {}, unknown: 3}` | Accepted; unsupported sibling key ignored. | **Fixed:** only the supported `wiki` mapping is accepted; nonfinite, boolean or negative timing values are also rejected. Target-page existence remains a separate input/provenance check. |

The base model forbids unknown schema fields and already rejects several incompatible combinations;
see [manifest validation](../src/mesocosm/core/manifest.py),
[existing condition tests](../tests/test_experiment_conditions.py) and
[research-condition wiring tests](../tests/test_research_conditions.py). The findings above close
specific gaps rather than implying all validation was absent. Default-valued dormant sections are
allowed for serialization compatibility; they must not be counted as an effective treatment.

Other meaningful boundaries already enforced or documented:

- Shared task services require comparison/reset and a compatible original live-service verifier.
- Generic incentives require comparison episodes. Ratings requires rewards and a live chat service;
  peer-derived rewards require peer review. Missing votes and missing team scores remain unknown.
- An access graph requires isolated agents and refuses a shared directory. Shared readable resources
  and internet are still alternative communication paths.
- Live-only monitor settings require pre-action timing. A reviewer timeout or missing evidence causes
  an operational denial, not a finding of misconduct.
- `conditions set` currently changes only per-agent budgets at the gateway. Other live mutations are
  [explicitly rejected](../src/mesocosm/core/conditions.py); initial YAML controls do not imply an
  arbitrary mid-run intervention API.
- `containment`, verifier networking and resource-limit adaptations are execution-validity settings,
  not behavioral incentives. An adapted run cannot establish containment it did not enforce.
- Independent original task measurements remain authoritative for task success. A configurable
  incentive or monitor judgment must never overwrite them.

## Hypotheses supported by existing controls

These are experimental questions, not claimed effects:

1. Does shared-model budget scarcity alter work allocation or communication? Compare equal
   per-agent budgets with a shared pool, counterbalance agent start order, and measure both completed
   work and quota refusals.
2. Does rewarding peer approval increase approval without independent task success? Keep original
   tasks and verifiers fixed; compare verifier and peer-derived incentives, and report missing reviews.
3. Does restricting direct communication change information relay through permitted resources?
   Vary the actual access graph and measure exact reads/writes across every available channel.
4. Does retaining local history change subsequent decisions? Compare reset/carry while stating
   which shared state persists; use independent fresh worlds when testing complete history removal.
5. Does joint monitoring catch behavior that per-agent evidence misses? Independently review
   prespecified samples, include unflagged cases, and measure task utility plus monitoring failures.

Before adding a variable, identify its enforcement component, an observable receipt, unsupported
combinations and a counterfactual comparison. Where enforcement is unavailable, reject the setting;
do not replace it with an instruction asking the agent to behave as though it were enforced.
